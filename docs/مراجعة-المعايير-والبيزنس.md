## الخلاصة التنفيذية

| المحور | التقييم | ملاحظة قصيرة |
|--------|---------|--------------|
| معمارية Service / Laravel | **جيد** | دورة العقود والصيانة والحسابات في Services |
| بيزنس العقود الأساسي | **جيد** | اعتماد · تسليم/توقيع · استلام · تمديد · تبديل · وديعة |
| SPA بلا رفريش + RTL | **جيد** | React SPA · sheets · toast · Arabic RTL |
| صلاحيات API (إنفاذ) | **ضعيف** | الصلاحيات تُرجَع في `/me` لكن المسارات غير محمية بـ Policy/middleware |
| فيتشر فلاج على API/Nav | **جزئي** | معرض وإخطار يرفضان عند الإطفاء؛ التنقّل والباقي لا يختفون تلقائياً |
| تغطية وحدات النطاق ن٫٢٢ | **جزئي ~70%** | نواقص: مصروفات، HR/مسير، محادثة، تقييمات، OCR، قوالب PDF كاملة، ربحية سيارة مفصّلة |
| اختبارات | **جزئي** | تسعير · FIFO · توفر · lifecycle سعيد؛ نقص فشل صلاحيات وحواف كثيرة |
| أمن (ط) | **يحتاج عمل** | Sanctum موجود؛ بلا FormRequest موحّد؛ بلا Policies؛ إعدادات المُدمج غير مفصولة على API |
| cPanel / MySQL | **متوافق بالتصميم** | لا Redis/WebSocket كاعتماد؛ SQLite محلي للاختبار فقط |

**الحكم:** نواة التأجير التشغيلية قابلة للاستخدام ومطابقة لمعظم قواعد قسم **ن** الحرجة. التسليم «كاملاً حسب ن٫٢٢» لم يكتمل؛ أهم فجوة تشغيلية الآن هي **إنفاذ الصلاحيات والفيتشر فلاج على API والتنقّل**.

## د) فجوات حرجة (مرتبة بالأولوية)

### P0 — أمن وتشغيل ملزم
1. **إنفاذ الصلاحيات على API**  
   كل مسار حساس (`approve`, `lock-month`, `petty-cash`, `blacklist`, `settings` feature flags…) يجب أن يتحقق من مفتاح PermissionCatalog أو Policy. حالياً أي توكن صالح يستدعي الكل.
2. **فصل PUT `/settings/tenant`**  
   مدير المعرض يعدّل `operational` فقط؛ `feature_flags` / `colors` / `multi_branch` للمُدمج فقط على مستوى API لا الواجهة فحسب.
3. **إخفاء الوحدات المطفأة من Nav + رفض API**  
   المعيار: «المطفأ = يختفي من التنقّل والصلاحيات ويُرفض من API». اليوم فقط showroom/department_notice يرفضان جزئياً.

### P1 — اكتمال بيزنس معلن
4. مصروفات تشغيل (CRUD + ترحيل).  
5. مسير رواتب / اعتماد HR.  
6. قوالب مطبوعة مع حفظ نسخة وقت الإصدار (عقد/فاتورة/إقرار/إيصال).  
7. وديعة: UI لخصم وردّ المتبقي + مسار رد تلقائي عند إنهاء مبكر.  
8. صور هوية/رخص للعميل في إخطار القسم (تخزين محلي آمن).

### P2 — جودة ومنتج
9. OCR داخلي (اقتراح حقول).  
10. محادثة بحدود · تقييمات.  
11. مولّد QR صورة.  
12. عداد تقديري أثناء التأجير.  
13. FormRequests بدل validate داخل Controllers.  
14. تقليل N+1 في dashboard/showroom.  
15. اختبارات فشل: صلاحية، توقيع ناقص، مستند منتهٍ، overlap، blacklist.

### Bugs مكتشفة أثناء المراجعة
| المكان | المشكلة | أثر |
|--------|---------|-----|
| `ReportController` | يعدّ `status = blacklisted` بينما النظام يستخدم `blacklist` | عداد السوداء في التقارير = 0 دائماً |
| فيتشر فلاج | Nav لا يقرأ الأعلام | وحدة مطفأة تبقى ظاهرة |
| InventoryController | إنشاء دفعة بدون Service/ترحيل محاسبي كامل | انحراف عن «بيزنس في Service» |

## هـ) ما يطابق المعايير بقوة (لا تكسره)

- دورة العقد في `ContractLifecycleService` + تسعير منفصل.  
- فحص وتوقيع في `InspectionService`.  
- FIFO في `FifoConsumptionService`.  
- مخالفات بلا ترحيل محاسبي.  
- تمديد/تبديل = عقد جديد.  
- SPA عربية RTL مع sheets وتغذية راجعة.  
- لوحة مُدمج مخفية عن غير `super_admin` في الواجهة.  
- وثائق API في `docs/API.md`.

## و) خطة إغلاق الفجوات المقترحة (بدون تقدير زمني)

1. Middleware/Policy: `permission:contracts.approve` إلخ على المسارات + اختبارات 403.  
2. تقسيم settings: `PUT /settings/operational` و`PUT /integrator/tenant` مفصولين.  
3. `featureFlags` من `/me` أو settings → تصفية `railNav` ورفض API موحّد.  
4. إصلاح عداد blacklist في التقارير.  
5. نقل waitlist/inventory receive إلى Services.  
6. وحدات P1 المتبقية حسب أولوية العميل (مصروفات ثم قوالب ثم HR).
