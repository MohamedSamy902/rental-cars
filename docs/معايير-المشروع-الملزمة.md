## ب) مبادئ الكود — Clean Code · SOLID · DRY

### ب٫١ Clean Code (ملزم)
- أسماء واضحة بالعربية في الواجهة وبالإنجليزية التقنية في الكود (`BookingService`, `createContract`) — بلا اختصارات غامضة.  
- دوال قصيرة تفعل شيئاً واحداً؛ ملفات/كلاسات بحجم مقروء.  
- بلا تعليقات تشرح «ماذا» إن كان الاسم يكفي؛ التعليق لـ «لماذا» عند قرار غير بديهي.  
- بلا سحر أرقام (`magic numbers`) — ثوابت مسماة أو إعدادات.  
- بلا منطق ميت أو كود معلّق (`commented-out`) في المين.  
- أخطاء تُعامل صراحة — لا `catch` فارغ ولا تجاهل فشل صامت.

### ب٫٢ SOLID على خدمات لارافيل والفرونت
| الحرف | المعنى عندنا |
|--------|----------------|
| **S** | كل Service / كومبوننت له مسؤولية واحدة واضحة (`ContractPricingService` ≠ `ContractPdfService`) |
| **O** | توسيع السلوك بإضافة Service/Strategy/Flag وليس بـ if عملاق يُعدَّل كل مرة |
| **L** | أي بديل لواجهة/عقد (Interface) يحترم نفس الضمانات |
| **I** | واجهات/عقود رفيعة؛ لا تجبر مستهلكاً على اعتمادات لا يحتاجها |
| **D** | الكنترولر والفرونت يعتمدان على تجريدات/خدمات؛ لا على تفاصيل تخزين أو HTTP خام مكررة |

### ب٫٣ DRY — عدم تكرار الكود
- قاعدة بيزنس واحدة = مكان واحد (Service)، تُستدعى من Controllers / Jobs / Commands.  
- فاليديشن مشترك في Form Request أو Rules قابلة لإعادة الاستخدام.  
- على الفرونت: كومبوننت حقل/جدول/شيت واحد؛ ممنوع نسخ JSX فورم لصق بين الصفحات.  
- توكنز الألوان والمسافات من CSS variables / ثيم واحد — ممنوع ألوان hex مبعثرة في كل ملف.  
- استثناء مسموح فقط عند اختلاف سلوك حقيقي موثَّق — ليس «نسخ أسرع».

### ب٫٤ مبادئ إضافية ملزمة
| المبدأ | التطبيق |
|---------|---------|
| KISS | أبسط حل صحيح؛ بلا طبقات زيادة «للمستقبل» |
| YAGNI | لا تُبنَى ميزة غير مطلوبة في هذا الملف / RSD |
| Fail fast | أوقف العملية عند خرق قاعدة بيزنس أو أمن مع رسالة واضحة |
| Least privilege | أقل صلاحية لازمة للمستخدم وللعملية |
| Explicit over implicit | حالات العقود والأسعار والصلاحيات صريحة في الكود لا «عرف ضمني» |

## ج) معمارية عامة · ستاك الفرونت

```
[ PWA / SPA عربي RTL — React + TypeScript ]
        ↕  API JSON
[ Laravel PHP — Controllers رفيعة → FormRequest → Service → Model/DB ]
        ↕
  Policies · Events · Jobs (عبر Cron على cPanel)
```

### ج٫١ ستاك التشغيل الداخلي (ملزم الآن)
| البند | القرار |
|--------|--------|
| فرونت التشغيل | **React + TypeScript** كـ **SPA/PWA** (بناء Vite أو ما يعادله) |
| لغة واجهة المستخدم | عربية فقط · RTL |
| نشر الفرونت | `npm run build` → ملفات ثابتة تُرفع مع/داخل Laravel `public` — **لا Node على السيرفر بعد الرفع** |
| باك | **Laravel (PHP)** + **Service فقط** للبيزنس |
| قاعدة البيانات | **MySQL** فقط (محرك InnoDB) — الحرف/الإصدار يُثبَّت عند بدء التنفيذ بما يناسب cPanel |
| Blade | **ليس** مصدر شاشات التشغيل اليومية؛ يجوز لاحقاً لصفحات عامة/SEO فقط |
| Next.js للتشغيل الداخلي | **غير معتمد** (يحتاج تعقيد نشر لا يناسب cPanel كمسار افتراضي) |

| الطبقة | المسموح | الممنوع |
|--------|---------|---------|
| Controller | استقبال ·authorize ·validate ·نداء Service ·استجابة | بيزنس ثقيل · SQL معقّد · ترحيل محاسبي |
| FormRequest | قواعد الحقول ورسائل عربية | قواعد دومين ثقيلة (تعارض حجز…) |
| **Service** | **كل البيزنس** · معاملات DB · أحداث | اعتماد على بيئة VPS-only |
| Model | علاقات · casts · scopes بسيطة | بيزنس متعدد الخطوات |
| Job/Listener | آثار جانبية (إشعار، ملف، PDF) تُستهلك عبر **Cron** | تجاوز Service للبيزنس الأساسي · افتراض worker دائم |
| Front page | تركيب كومبوننتس + ربط API | تكرار منطق تسعير/ترحيل في الواجهة كمصدر حقيقة |

### ج٫١٫١ قاعدة البيانات — MySQL (ملزم)
- قاعدة البيانات الإنتاجية والتطويرية للمشروع: **MySQL**.  
- محرك الجداول: **InnoDB** (معاملات، مفاتيح أجنبية، تناسق).  
- ترميز: **utf8mb4** · ترتيب مناسب للعربية.  
- ممنوع اعتماد PostgreSQL / SQL Server / SQLite للإنتاج (SQLite مسموح فقط لاختبارات معزولة إن لزم دون أن يكون هدف النشر).  
- كل عميل نهائي: قاعدة MySQL مستقلة (أو schema معزول حسب نموذج النسخة على cPanel).  
- الهجرات عبر Laravel Migrations فقط — بلا تعديل يدوي صامت على الإنتاج.

**نموذج التسليم:** كل عميل نهائي = بيئة/نسخة مستقلة (ليست SaaS مشتركة في واجهة واحدة للعملاء).  
**لوحة المُدمج:** طبقة فوق/بجانب النسخة — خاصة بمقدّم النظام فقط (قسم م).

## ج٢) الاستضافة: cPanel فقط — ملزم للايف

بيئة الإنتاج المستهدفة: **cPanel فقط** (استضافة مشتركة/مدارة بـ cPanel).  
**لا يُفترض** VPS أو Docker أو Supervisor أو Node دائم أو Redis مخصّص ما لم يُتفق لاحقاً كتابةً ويُحدَّث هذا الملف.

### ج٢٫١ ماذا يعمل على cPanel؟
| المكوّن | الوضع |
|---------|--------|
| Laravel + PHP + **MySQL** | نعم — المسار الأساسي (على بعض cPanel يظهر MariaDB كمحرك متوافق مع MySQL ويُقبل إن لم يتوفر MySQL باسمه) |
| فرونت React بعد البناء (static) | نعم — يُرفع كملفات |
| SSL / دومين من cPanel | نعم |
| نسخة مستقلة لكل عميل (مجلد + DB) | نعم — النموذج المعتمد |
| Cron من لوحة cPanel | نعم — بديل الـ workers |

### ج٢٫٢ بدائل إلزامية بدل أدوات الـ VPS
| على VPS غالباً | البديل الملزم على cPanel |
|----------------|---------------------------|
| `queue:work` / Supervisor دائم | **Cron** دوري: `schedule:run` و/أو `queue:work --stop-when-empty` |
| Redis للكاش/الطوابير/الجلسات | **database** أو **file** (حسب إعداد لارافيل المتاح) |
| WebSockets لبث فوري | **Polling** خفيف و/أو إعادة جلب عند تركيز النافذة — مع الإبقاء على SPA بلا رفريش صفحة |
| Node.js دائم (Next SSR للتشغيل) | ممنوع كاعتماد إنتاج؛ SPA static فقط للتشغيل |
| جدولة نظام معقّدة | مهمة cron واحدة (أو عدد محدود) تستدعي جدولة لارافيل |
| بناء على السيرفر (`npm`/`composer` الثقيل) | البناء على جهاز التطوير أو CI ثم رفع الناتج جاهزاً |

### ج٢٫٣ قيود تصميم بسبب cPanel
- لا تُبنَى ميزة تعتمد على WebSocket أو Redis أو worker دائم دون بديل cPanel موثَّق في نفس الـ PR.  
- العمليات الثقيلة (PDF دفعة، إشعارات جماعية) → طابور قصير + Cron، مع حدود زمنية مناسبة للاستضافة المشتركة.  
- رفع الملفات والصور بحجم أقصى واضح متوافق مع حدود الاستضافة.  
- الباك أب الإنتاجي: آلية cPanel / نسخ يومية وفق المواصفة؛ مكان الحفظ في محضر التسليم.  
- أي أداة تطوير محلية (Docker للراحة) **لا تُصبح** متطلباً للايف.

### ج٢٫٤ مرحلة لاحقة — موقع العملاء (SEO) تحت نفس القيد
حجز ذاتي من الإنترنت **خارج نطاق التسليم الحالي**، لكن المسار المستقبلي محجوز كالتالي (بدون تنفيذ الآن):
- موقع عام بـ SEO منفصل عن PWA الموظفين.
- على cPanel يُنفَّذ لاحقاً بأحد بدائل بلا Node دائم: صفحات Laravel عامة، أو تصدير static (مثل static export)، أو موقع ثابت + API.
- لا يُعاد كتابة شاشات التشغيل إلى Next بسبب هذه المرحلة.

## د) SPA / Realtime / بلا رفريش — ملزم بقوة

هذا بند **غير قابل للتفاوض**. المنتج يجب أن يبدو كتطبيق: سريع، سلس، بدون وميض إعادة تحميل.

### د٫١ ماذا يعني «بلا رفريش»؟
| العملية | السلوك الملزم |
|---------|----------------|
| التنقّل بين الصفحات | Client-side routing (SPA) — **بدون** إعادة تحميل المستند كاملة |
| إضافة سجل | API → تحديث القائمة/الحالة فوراً → الشيت يُغلق أو يصفّر حسب السياق |
| تعديل سجل | API → تحديث البطاقة/الصف فوراً دون رفريش |
| حذف (ناعم عادة) | API → إزالة/وسم العنصر فوراً مع تأكيد |
| فاليديشن فاشل | الحقول تبقى كما هي؛ أخطاء تحتها؛ **لا** رفريش يضيّع الإدخال |
| تغيير فلتر/بحث | يحدّث النتائج فوراً (debounce للبحث) بلا رفريش |
| تبديل تبويب/شيت | حالة محلية؛ بلا إعادة تحميل الصفحة |
| بعد نجاح عملية | Toast/رسالة قصيرة؛ السياق يبقى (نفس الشاشة/الفلتر) |

### د٫٢ ممنوعات صريحة
- `window.location.reload` / `location.href` للتنقّل الداخلي أو بعد CRUD.  
- نماذج HTML تقليدية تعمل full page submit لصفحات التشغيل.  
- الاعتماد على «المستخدم يعمل رفريش عشان يشوف التحديث».  
- إخفاء الفورم بالكامل عند أول خطأ خادم دون الإبقاء على القيم.

### د٫٣ سرعة الإحساس + حركة ناعمة (Smooth motion) — ملزم
- انتقال الصفحات فوري مع هيكل التطبيق ثابت (شلّ + outlet).  
- **الحركة ناعمة (smooth)** في كل التفاعلات المرئية: فتح/إغلاق الشيت، ظهور التوست، تبديل التبويب، توسّع القوائم، انتقال المحتوى داخل الشلّ.  
- مدة الحركة المعتادة قصيرة ومحسوبة (حوالي ١٥٠–٣٠٠ms)؛ easing طبيعي — بلا قفزات حادة ولا وميض.  
- احترام `prefers-reduced-motion` (اختصار أو إلغاء الأنيميشن غير الضروري).  
- الحركة لخلق وضوح وتسلسل — **ممنوع** أنيميشن زخرفي يبطّئ أو يشوّش.  
- Optimistic UI مسموح حيث آمن (مع rollback ناعم عند الفشل).

### د٫٤ دليل التحميل (Loading feedback) — ملزم بقوة
**ممنوع** أن تبدو الشاشة «معلّقة» بلا إشارة. أي انتظار ملحوظ له دليل واضح:

| الموقف | الدليل الملزم |
|--------|----------------|
| أول تحميل قائمة/صفحة | **Skeleton** بنفس تخطيط المحتوى (أو مؤشر منطقة) — الشلّ يبقى ظاهراً |
| زر حفظ/اعتماد/حذف | حالة loading على الزر + **منع دبل-سابمت** |
| تبديل فلتر/بحث بانتظار شبكة | مؤشر خفيف على منطقة النتائج (بدون مسح التخطيط كله إن أمكن) |
| رفع ملف / توليد PDF / عملية أطول | مؤشر تقدّم أو spinner + رسالة عربية («جاري التحميل…») |
| تحديث صامت في الخلفية | إن > ~300ms يظهر مؤشر غير مزعج |
| فشل بعد تحميل | يختفي اللود → **ErrorState** أو رسالة؛ لا يبقى سبنر للأبد |

قواعد:
- أي عملية متوقعة > ~300ms → مؤشر مرئي إلزامي.  
- اللود من عائلة موحّدة (`Skeleton` / `Spinner` / زر loading) — بلا شكل مختلف لكل شاشة.  
- بعد انتهاء اللود: انتقال ناعم للمحتوى وليس اختفاء مفاجئ.

### د٫٥ تزامن العرض
- بعد نجاح الكتابة: مصدر الحقيقة يُحدَّث في كاش/ستور العميل فوراً.  
- إن وُجد أكثر من مستخدم: **Polling** و/أو إعادة جلب عند التركيز/حدث — **بدون** رفريش صفحة.  
- WebSockets ليست اعتماداً للإنتاج على cPanel (انظر ج٢).

## هـ) UI / UX / نظام التصميم (مقفول)

### هـ٫١ هوية بصرية افتراضية
| العنصر | القيمة |
|--------|--------|
| لغة/اتجاه | عربي · RTL فقط |
| شريط تنقّل | `#0B1220` |
| خلفية | `#F1F5F9` |
| بطاقة | `#FFFFFF` |
| نص | `#0F172A` / ثانوي `#64748B` |
| علامة/CTA | `#0D9488` |
| نجاح / تحذير / خطر | `#059669` / `#D97706` / `#DC2626` |
| حدود | `#E2E8F0` · نصف قطر ٨–١٢px |

الألوان للمستأجر تُغيَّر من **لوحة المُدمج فقط**.  
ممنوع: بنفسجي AI · كريمي+تيراكوتا · ستايل صحيفة · دارك مود افتراضي · Glow مبالغ.

### هـ٫٢ شكل المنتج
- PWA كأنّه تطبيق: شريط سفلي على الضيق · شيتات · أهداف لمس كبيرة.  
- تابلت/أعرض: قائمة يمين داكنة + جداول أكثف حيث يناسب.  
- الصفحة الرئيسية: بطل إشغال · KPI · شارتات · إجراءات سريعة · مهام اليوم.  
- القوائم: **ملخص أعلى** + بحث + فلاتر شيبس + كروت/جداول حسب العرض.  
- الفورمات: كاملة حسب جداول RSD — ممنوع «لاحقاً».

### هـ٫٢٫١ Responsive على كل الشاشات — بلا استثناء (ملزم بقوة)
الفرونت **يجب** أن يعمل بشكل سليم ومقروء وقابل للاستخدام على **كل** أحجام الشاشات والمعلومات التخطيطية — **بدون أي شاشة مستثناة**.

| الفئة | أمثلة يجب تغطيتها |
|--------|-------------------|
| موبايل ضيق | هواتف صغيرة وكبيرة عمودي/أفقي |
| موبايل قابل للطي (Fold) | وضع مطوي · مفتوح · شاشة غلاف · تغيّر العرض أثناء الاستخدام |
| تابلت | عمودي وأفقي |
| لابتوب / سطح مكتب | نوافذ ضيقة وكاملة · شاشات عريضة |
| أي viewport وسيط | لا «نقطة عمياء» بين البريكات |

قواعد ملزمة:
- تخطيط **fluid / breakpoints** واضح؛ المحتوى لا يخرج أفقياً ولا يتكدس فوق بعضه ولا يُقطع.  
- لا اعتماد على عرض ثابت بـ px للصفحات التشغيلية؛ استخدم نسب/flex/grid ووحدات مرنة.  
- الجداول العريضة: على الضيق تتحوّل لكروت أو تمرير أفقي مضبوط داخل الحاوية مع بقاء الإجراءات واضحة — **ممنوع** كسر الصفحة أفقياً.  
- الشيتات/المودالات/الفورمات تتكيّف مع الارتفاع والعرض (خصوصاً الكيبورد على الموبايل والفولد).  
- أهداف اللمس كافية على اللمس؛ على سطح المكتب التفاعل بالماوس يبقى مريحاً.  
- عند تغيّر حجم النافذة أو طي/فتح الفولد: إعادة تخطيط **ناعمة** بلا اختفاء أزرار أو حقول أساسية.  
- اختبار يدوي إلزامي قبل تسليم شاشة على: موبايل ضيق · موبايل واسع/فولد مفتوح · تابلت · ديسكتوب.  
- **ممنوع**: شاشة «ديسكتوب فقط» أو «موبايل فقط» داخل نطاق التشغيل · أو سكرول أفقي لجسم الصفحة كله.

### هـ٫٣ Zero detour (٣٫٢١)
أي كيان ناقص أثناء تدفق → إضافة مضمّنة في نفس الشيت ثم اختيار تلقائي.  
ممنوع: مسودة → شاشة أخرى → رجوع.

### هـ٫٤ الرسائل للمستخدم
- نجاح عربي مختصر.  
- خطأ فاليديشن على الحقل.  
- خطأ صلاحية/خادم مفهوم — ليس stack إنجليزي خام.

### هـ٫٥ الحركة واللود (ملخص UX)
- الواجهة **سموث**: انتقالات ناعمة للشيتات والصفحات والتنبيهات.  
- كل تحميل له دليل ظاهر (Skeleton / زر loading / رسالة «جاري…»).  
- لا شاشة صامتة معلّقة · لا قفز محتوى بلا انتقال · لا أنيميشن يعيق الاستخدام.

## و) نظام الكومبوننتس وتوحيد الحقول (Front)

### و٫١ طبقات الفرونت
```
pages/          → صفحات تركيب فقط
features/<domain>/ → منطق الشاشة + hooks
shared/ui/      → كومبوننتس العرض الموحّدة (Button, Field, Sheet, Table…)
shared/api/     → عميل HTTP + معالجة 401/403/422
shared/lib/     → تنسيق تاريخ/عملة/أرقام
```

### و٫٢ كومبوننتس إلزامية موحّدة (لا تُعاد كتابتها في كل صفحة)
| كومبوننت | الاستخدام |
|----------|-----------|
| `AppShell` | هيكل + تنقّل + منفذ الصفحات |
| `PageHeader` | عنوان + أكشن أساسي |
| `SummaryStrip` | ملخص أرقام أعلى القائمة |
| `FilterBar` | بحث + شيبس |
| `DataList` / `DataTable` | كروت موبايل / جدول تابلت |
| `StatusPill` | حالات ملوّنة موحّدة |
| `Sheet` / `Modal` | إضافة/تعديل |
| `Form` + `FormSection` | تجميع حقول |
| `Field*` | انظر توحيد الحقول |
| `InlineCreate` | إضافة مضمّنة (Zero detour) |
| `ConfirmDialog` | حذف/إجراء خطير |
| `Toast` / `Banner` | نجاح/خطأ عام |
| `EmptyState` / `ErrorState` / `Skeleton` / `Spinner` | حالات فارغ/خطأ/تحميل — **إلزامية** عند الانتظار |
| `Button` بحالة `loading` | نفس الزر يظهر لود ويمنع التكرار |
| `PermissionGate` | إظهار حسب صلاحية (مع حماية API إلزامية) |

كل الحقول في النظام من عائلة واحدة:

| النوع | كومبوننت | ملاحظات عرض |
|--------|----------|-------------|
| نص | `TextField` | تسمية فوق · خطأ تحت · نفس الارتفاع/الحد |
| رقم/عملة | `NumberField` / `MoneyField` | ج.م · فواصل عربية موحّدة |
| تاريخ/وقت | `DateField` / `DateTimeField` | نفس الـ picker |
| قائمة | `SelectField` / `SearchSelect` | مع «+ إضافة من هنا» إن Zero-detour |
| نعم/لا | `SwitchField` | |
| ملف/صورة | `FileField` | معاينة + قيود حجم/نوع |
| توقيع | `SignatureField` | |
| نص طويل | `TextAreaField` | |

**قواعد توحيد:**
- نفس المسافة بين التسمية والحقل ونص الخطأ في كل الشاشات.  
- نفس حجم الخط والحدّ والتركيز (`focus`) من الثيم.  
- الحالة: default / focus / error / disabled / readOnly — موحّدة.  
- الحقل الإلزامي بعلامة واضحة موحّدة.  
- ممنوع حقول «ستايل حر» داخل صفحة واحدة تكسر العائلة.

### و٫٤ حالة البيانات على الفرونت
- مصدر حقيقة للعمليات عبر API؛ الفرونت لا يخترع ترحيل محاسبي.  
- معالجة موحّدة لـ `422` → ربط `errors[field]` بالحقول.  
- صلاحيات من الـ API/جلسة؛ الإخفاء للراحة فقط وليس أمناً.

### ز٫١ التدفق الإلزامي
`Route → Middleware(auth,throttle,…) → Controller → FormRequest → Service → (DB/Events) → JSON Resource`

### ز٫٢ تنظيم Services
```
app/Services/
  Contracts/ContractService.php

  Inventory/FifoConsumptionService.php
```

- استثناءات دومين واضحة (`DomainException` / أنواع مخصّصة) تُترجم لاستجابة API.

### ز٫٣ ممنوع
- بيزنس في Blade/Front كمصدر حقيقة.  
- نسخ نفس استعلام التوفر في ٣ كنترولرز.  
- Repository إلزامي مسبقاً — يُضاف فقط إن حل تكراراً حقيقياً دون كسر Service.  
- Fat Model يحوي سيناريوهات كاملة.

## ح) الفاليديشن ورسائل الخطأ

1. **كل كتابة** لها FormRequest (أو ما يعادله).  
2. رسائل عربية في `messages` / `attributes`.  
3. شكل موحّد لـ `422`:
```json
{
  "message": "تعذّر الحفظ. راجع الحقول.",
  "errors": {
    "phone": ["رقم الهاتف غير صالح."]
  }
}
```
4. فاليديشن بيزنس داخل Service (تعارض حجز، رصيد سالب، مستند منتهٍ…) → `422` أو `409` برسالة عربية واضحة.  
5. الفرونت يعرض خطأ الحقل تحته + لا يمسح الإدخال.  
6. لا تُرجع تفاصيل داخلية (SQL, paths, secrets) للمستخدم.

## ط) الأمن (Security) — ملزم بالكامل

### ط٫١ مصادقة وجلسة
- مصادقة إلزامية لكل API تشغيلي (ما عدا مسارات عامة محددة مثل QR الزائر المعرّفة في RSD).  
- انتهاء جلسة حسب الإعداد؛ تسجيل خروج يُبطل التوكن/الجلسة.  
- كلمات مرور: hashing قوي (خوارزمية Laravel الافتراضية المعتمدة) · سياسة طول/تعقيد معقولة.  
- حماية من Credential stuffing: rate limit على login.  
- لا تُخزَّن كلمات مرور أو أسرار في المستودع أو اللوجات.

### ط٫٢ صلاحيات
- **Policies / Gates** على كل إجراء حساس (اعتماد عقد، إقفال شهر، رد تأمين، مسح، تصدير هويات…).  
- الفرونت يخفي؛ الـ API **يرفض** (403) دائماً.  
- أدوار افتراضية من RSD قابلة للتوسعة؛ الصلاحيات الحساسة لا تُمنح ضمناً.  
- لوحة المُدمج: مصادقة منفصلة/أعلى صلاحية — ليست دور موظف معرض.

### ط٫٣ حماية الطلبات والبيانات
| التهديد | التحكم |
|---------|--------|
| CSRF | تفعيل لحماية جلسة الويب حسب ستاك المصادقة |
| XSS | React escaping افتراضي · CSP مناسب · لا `dangerouslySetInnerHTML` بلا تبرير وتعقيم |
| SQL Injection | Eloquent/Query Builder مُعلَّم؛ بلا SQL خام بمدخلات مستخدم |
| Mass Assignment | `$fillable` / `$guarded` صارمة؛ لا تمرير request->all للنموذج |
| IDOR | كل استعلام يقيّد بالمورد المصرّح به (ونطاق النسخة/الفرع) |
| File upload | أنواع مسموحة · حجم أقصى · تخزين خارج web root إن أمكن · إعادة تسمية · فحص محتوى |
| Path traversal | مسارات ملفات عبر معرفات لا عبر مسار مستخدم خام |
| SSRF | لا تُجلب URLs من المستخدم لخوادم داخلية |
| Secrets | `.env` فقط · ليس في Git · تدوير عند التسريب |

### ط٫٤ بيانات شخصية وحساسة (مصر)
- الرقم القومي وصور الهوية: إخفاء/عرض حسب صلاحية (RSD).  
- سجلات الوصول والتعديلات للعمليات الحساسة.  
- صور المستندات لا تُرسل لخدمات خارجية (قاعدة ٣٫١٦).  
- تصدير البيانات مقصور بصلاحية ويُسجَّل.  
- حذف ناعم للمالي والمرفقات الحساسة — بلا مسح نهائي كسلوك افتراضي.

### ط٫٥ البنية والاستضافة
- الإنتاج على **cPanel فقط** وفق قسم **ج٢** — بلا افتراض VPS.  
- HTTPS فقط في البيئات المعروضة.  
- رؤوس أمان ملائمة (CSP أساسي، X-Content-Type-Options، Frameguard حسب الحاجة).  
- تحديثات اعتمادات أمنية؛ لا مكتبات مهجورة حرجة معروفة.  
- النسخ الاحتياطي: يومي لقاعدة البيانات والملفات مع احتفاظ ٣٠ يوماً (كما في RSD)؛ مكان الحفظ في محضر التسليم؛ تفضيل نسخة لا تعتمد على نفس قرص الانهيار إن أتاح المزود.  
- مبدأ البيئة المستقلة لكل عميل يقلّل مخاطر الاختلاط بين العملاء.

### ط٫٦ سجل ومراقبة أمنية
- سجل دخول فاشل/ناجح.  
- سجل تعديلات للحقول الحساسة.  
- لا تُسجَّل أسرار ولا أجساد بطاقات كاملة في اللوجات.

## ي) الأداء (Performance) — ملزم

### ي٫١ أهداف رقمية (بيئة التسليم المتفق عليها)
| المقياس | الهدف |
|---------|--------|
| عرض قائمة حتى ٥٠٠ سجل | < ٣ ثوانٍ على اتصال ≥ ١٠Mbps (كما في RSD) |
| التنقّل بين صفحات الشلّ | فوري إحساساً (< ١٠٠ms لرسم الهيكل؛ بيانات قد تكتمل لاحقاً) |
| حفظ فورم بسيط | استجابة API مستهدفة < ٥٠٠ms على بيانات معتدلة؛ مؤشر إن طال |
| First meaningful paint للوحة | هيكل + ملخص أولي بسرعة؛ الشارتات قد تُحمَّل لاحقاً |
| حجم حزمة JS الأولية | تُقسَّم بالكود-سبليت حسب المسارات؛ لا تُحمَّل كل الشاشات مرة واحدة بلا حاجة |

### ي٫٢ باك اند
- فهرسة DB لكل أعمدة البحث/الفلاتر/FK شائعة (تواريخ عقود، حالة سيارة، فرع…).  
- تجنّب N+1: `with()` / تحميل واعٍ.  
- صفحات API (`pagination`) للقوائم — لا تُرجع ١٠ آلاف صف افتراضياً.  
- تجميع تقارير ثقيلة في Queries محسّنة أو جداول ملخّصة/كاش عند الحاجة.  
- طوابير للعمليات الثقيلة (PDF دفعة، إشعارات جماعية، استيراد) تُفرَّغ عبر **Cron** على cPanel.  
- كاش إعدادات/ثيم/فيتشر فلاج بمدة قصيرة (file/database) مع إبطال عند التعديل من المُدمج — بلا افتراض Redis.

### ي٫٣ فرونت
- Code splitting للمسارات.  
- صور مضغوطة · أحجام مناسبة للموبايل · lazy للصور غير الظاهرة.  
- افتراضي/virtualization للجداول الطويلة جداً إن لزم.  
- Debounce للبحث.  
- عدم إعادة تصيير الصفحة كاملة عند تحديث صف واحد.  
- إبقاء الشلّ ثابتاً؛ تبديل المحتوى فقط.

### ي٫٤ قياسات
- قبل تسليم ميزة قائمة كبيرة: قياس زمن API + زمن عرض.  
- منع رجوع أداء واضح مقارنة بالمعيار أعلاه دون موافقة وتوثيق.

## ك) البيانات · التزامن · الملفات

- معاملات DB حول: اعتماد عقد، استلام، إقفال شهر، تبديل عطل، استهلاك FIFO، رد تأمين.  
- حذف ناعم للكيانات المالية؛ قيود تمنع يتماً مرجعياً يكسر التقارير.  
- تسميات ملفات موحّدة؛ ربطها بالكيان؛ صلاحية الوصول عبر API لا رابط عام عشوائي إن كانت حسّاسة.  
- ترحيل محاسبي من Service واحد لكل نوع حركة حسب جداول RSD — بلا ترحيل مزدوج صامت.  
- منطقة زمنية وآلة تاريخ موحّدة للعرض والتخزين وفق إعدادات مصر/التسليم.

## م) لوحة المُدمج (ليست للعميل النهائي)

خاصة بمقدّم النظام / المُدمج فقط — **لا رابط ولا صلاحية لموظفي المعرض.**

| الإعداد | الأثر |
|----------|--------|
| كل الألوان | ثيم المستأجر |
| تعدد فروع؟ نعم/لا | إظهار/إخفاء تعقيد الفروع |
| اسم المركز + اللوجو | بارزان عند فرع واحد |
| وضع المخزن | موحّد لكل الفروع أو لكل فرع (إن تعدد الفروع = نعم) |
| فيتشر فلاج لكل وحدة | إظهار/إخفاء أي وحدة (مخزون، عهدة، انتظار، معرض، إخطار قسم، محادثة، تقييمات، HR، …) |

المطفأ = يختفي من التنقّل والصلاحيات ويُرفض من API.  
إعدادات التشغيل اليومية للمعرض (أسعار، تنبيهات…) شاشة منفصلة لمدير المعرض.

## ن) البيزنس الملزم (يُطابق RSD ٣٫٤)

### ن٫١ ثوابت المنتج
- لغة الواجهة: العربية فقط · التشغيل: مصر · العملة: الجنيه المصري فقط.  
- الإيجار باليوم فقط — لا ساعة.  
- فرع واحد افتراضياً؛ التعدد اختياري من لوحة المُدمج.  
- تتبع: حقلا رقم الجهاز ورقم الشريحة فقط — بلا خريطة حية وبلا نقل جهاز.  
- ملغى صراحة: فرق وقود محاسبي · دليل جهات · رصيد دائن للعميل · غرامة تأخير منفصلة · واتساب/SMS · فاتورة ضريبية حكومية · حجز العميل لنفسه من الإنترنت.

### ن٫٢ عدّ الأيام (٣٫١)
إيجار بأيام كاملة؛ أي امتداد بعد ساعة البداية = يوم إضافي.  
أيام الإغلاق من البداية حتى الإرجاع الفعلي (أو وفق إنهاء مبكر).  
الكيلومترات المسموحة = بدل يومي مثبّت × أيام الإغلاق.

### ن٫٣ التأخير (٣٫٢)
تأخير إرجاع العميل = أيام إيجار إضافية **موسومة تأخير** — ليست غرامة منفصلة.

### ن٫٤ الإجمالي النهائي (٣٫٣)
`إيجار المدة (يشمل التأخير الموسوم) − خصم + كيلومترات زيادة + أضرار + رسوم تأمين تشغيل + رسوم أخرى`  
الوديعة خارج الإجمالي. لا فرق وقود ولا غرامة تأخير منفصلة.

### ن٫٥ تثبيت الأسعار (٣٫٤)
عند الاعتماد تُثبَّت: سعر يومي · بدل كم · سعر زيادة · وديعة متفق · رسوم تشغيل · حد أدنى أيام.

### ن٫٦ إنهاء مبكر (٣٫٥)
إيجار على الفعلي مع احترام الحد الأدنى إن وُجد؛ الزيادة تُردّ بحركة **مدفوع للعميل** — بلا رصيد دائن.

### ن٫٧ توزيع الشهور وإقفالها (٣٫٦–٣٫٧)
إيجار بنسبة أيام الشهر؛ الزيادة/أضرار/رسوم على شهر الاستلام/الإغلاق.  
إقفال شهر يمنع التعديل؛ إعادة الفتح بصلاحية+سبب+سجل.

### ن٫٨ حالات السيارة والعقد (٣٫٨)
متاحة / محجوزة / مؤجرة / صيانة / خارج الخدمة / مباعة حسب التاريخ والعقود وأوامر الشغل.  
حالات العقد: معلّق · معتمد · نشط · مكتمل · ملغى — بالمعاني في RSD.

### ن٫٩ إلغاء (٣٫٩)
قبل التسليم مع صلاحية؛ رد المقبوض بلا رصيد دائن. بعد التسليم → إنهاء مبكر/استلام لا «إلغاء».

### ن٫١٠ عداد تقديري وتنبيهات (٣٫١٠)
أثناء التأجير فقط وفق المعادلة في RSD؛ مرجع التنبيه يفضّل العداد الفعلي الأحدث.

### ن٫١١ مخالفات (٣٫١١ + ٣٫١٨)
إسناد حسب الحيازة؛ متابعة وتأكيد سداد **دون ترحيل محاسبي** ودون دخولها إجمالي العقد.

### ن٫١٢ مستندات ورخص (٣٫١٢)
منع اعتماد عند انتهاء إن فُعّل الإعداد؛ تحذير إن ينتهي قبل نهاية العقد.

### ن٫١٣ صيانة × حجوزات (٣٫١٣)
لا تحويل لصيانة صامت مع تعارض عقود — رفض أو معالجة صريحة.

### ن٫١٤ تأكيد عميل (٣٫١٤)
توقيع عند التسليم (افتراضي إلزامي)؛ عند الاستلام حسب الأضرار/الخصم.

### ن٫١٥ مسافة (٣٫١٥)
المصطلح: كيلومتر / كيلومترات زيادة فقط.

### ن٫١٦ OCR داخلي (٣٫١٦)
اقتراح حقول بمراجعة موظف؛ **لا إرسال صور هوية لخدمة خارجية**.

### ن٫١٧ تبديل عطل (٣٫١٧)
إغلاق حيازة القديمة + **عقد جديد** للبديلة مع نسخ ووسم وربط؛ إيراد بلا أيام مزدوجة؛ ترحيل متبقي الوديعة؛ كم زيادة لكل عقد على حدة.

### ن٫١٨ تمديد (٣٫١٩)
= **عقد جديد** موقَّع؛ إيراد على أيام الجديد فقط.

### ن٫١٩ إخطار القسم (٣٫٢٠)
طباعة فورية بفلاتر الفترة/عميل.

### ن٫٢٠ مخزون وصيانة
- صرف من أمر الشغل بـ **FIFO** أو شراء (من العهدة أو لا).  
- بلا أوامر صرف مخزني منفصلة كمستند إلزامي معقّد.  
- إغلاق أمر شغل يحدّث الحالة/التوقف/الاستهلاك.

### ن٫٢١ فروع ومخزن (٣٫٢٣)
| وضع | سلوك |
|------|------|
| تعدد = لا | فرع ضمني؛ اسم+لوجو بارزان؛ بلا قوائم فرع |
| تعدد = نعم | فلترة بالفرع والصلاحية |
| مخزن موحّد / لكل فرع | حسب المُدمج عند التعدد |

### ن٫٢٢ وحدات النطاق (ملخص)
أسطول · حجوزات/تقويم · انتظار · وضع معرض · QR · فحص/مستلزمات · وديعة · عملاء/قائمة سوداء · مخالفات متابعة · صيانة/مخزون/عهدة · مصروفات · حسابات وتوزيع شهور ومقارنة ربحية · HR وتقييمات · قوالب مطبوعة · إشعارات داخلية · محادثة بحدود · إحصائيات بمعادلات · سجل تعديلات · صلاحيات كاملة · إخطار قسم.

### ن٫٢٣ جداول الحقول

إن تعارض جدول مع قسم **ن** هنا يُصلح التعارض صراحة في الملفين.
